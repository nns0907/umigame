# コミットメッセージ規約

本プロジェクトでは、プロジェクトの健全性と履歴の可視性を保つため、**Conventional Commits** をベースにした以下の規約を採用します。

## メッセージの基本構成

```text
<type>: <主な変更内容（日本語）>
```

※「なにを目的とした変更か」を一目で判断できるよう、必ず接頭辞（Type）を付与してください。

## 接頭辞（Type）の定義

| 接頭辞 | 意味 | 使用シーン |
| :--- | :--- | :--- |
| **`feat`** | 機能追加 | 新しい機能、画面、APIなどの追加 |
| **`fix`** | 不具合修正 | バグ修正、不整合の解消 |
| **`docs`** | ドキュメント | Markdownファイル、コメント、ドキュメントの更新 |
| **`chore`** | 雑務・設定 | ビルド設定、パッケージ更新、環境構築、不要なファイル削除 |
| **`refactor`** | リファクタリング | 挙動を変えずにコードの構造を改善した時 |
| **`test`** | テスト | テストコードの追加、修正 |
| **`style`** | スタイル | 機能に影響しないフォーマット修正（インデント等） |

## 具体的なコミット例

*   `feat: 問題一覧画面のコンポーネントを作成`
*   `fix: データベース接続エラーの解消`
*   `docs: 実行環境セットアップ手順の追記`
*   `chore: 不要な初期生成ファイルの削除`

---

> [!TIP]
> 履歴を美しく保つことは、プロジェクトの長期的なメンテナンス性を高める第一歩です！
